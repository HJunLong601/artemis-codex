# 视觉定位缓存

[English](./visual-location-cache.md)

定位优先级为 **ADB/UI 树 → 本地视觉位置缓存 → 图片 OCR/模型**。正常的 ADB 操作和 XML 定位不查询该缓存。每台设备独立维护持久化的 **10,000 条位置 LRU**，内部按系统界面、桌面、应用分组，再按应用包名、页面指纹、屏幕尺寸、目标和定位策略区分。同一设备各分组共享 10,000 条额度，命中后更新最近使用顺序，满额时优先淘汰未使用的预缓存，其余按最近使用顺序保留。每条记录对应一个位置，不会自动播放整条点击链路。

缓存后台的“页面名称”由视觉定位时顺带概括，支持搜索；同一 Activity 下可区分不同名称。名称仅作为展示元数据，不参与指纹匹配，不增加缓存条目。旧记录和无法判断的页面显示“未识别”，后续实际视觉定位时补充，不为补名称单独调用模型。

## 学习与容量

首次需要视觉定位时，Flash 与 Pro/Ultra 在同一次请求中顺带提取最多 20 个常用可见控件（名称、最多 3 个初始别名、类型、边界和坐标）。不为批量学习单独调用模型，但输出 token 和首次响应耗时可能增加。唯一、规范化且精确匹配的别名可复用，歧义目标继续正常定位。同一边界或同名且点落在已有边界内的按需结果会合并到已有元素。名称不新增元素额度。

页面学习记录区分学习中、已完成、部分淘汰、空结果、失败和已失效。补齐只随下一次实际视觉定位进行；部分淘汰冷却 30 秒，空结果/失败冷却 60 秒，学习占用 120 秒后可重试，晚到的旧请求不能覆盖新请求。未使用预缓存最多占每设备 `min(capacity, max(20, capacity // 5))` 条，默认 2000 条；首次命中后进入优先保留队列。总容量仍默认 10,000，显式配置 2000 继续有效。`batch_prefetch: false` 关闭新增批量提取，保留已有缓存复用。

## 复用保护

“UI 未变化”通过**主体界面**的解码像素和 UI 树精确校验，不用感知哈希近似判断。明确的 UI 节点或 Android 系统提供的可见 inset 用于识别状态栏，因此其中的时间、电量和图标变化不会影响主体未变时的命中。状态栏节点及 UI 转储中的节点序号不纳入页面指纹。不按固定顶部百分比裁切；边界未知、隐藏、冲突或过大时回退到完整截图比对。顶部应用控件可能与状态栏重叠时也不屏蔽该区域。

整页精确匹配失败后，候选仍限定同一设备、应用、Activity 和屏幕尺寸。相同非空 UI 结构可进入局部校验；结构签名忽略目标外的文字及辅助无障碍标签，局部范围内的节点属性（包括文字）仍须一致。候选必须有明确边界，局部区域向外扩展至少 8 像素或短边 2.5%。局部图像缩到最多 128 像素宽，再进行颜色量化以容忍轻微压缩噪声；它不是原始像素完全相等校验。若页面其他位置的结构改变，还须在目标附近找到唯一、可见、启用的可点击节点，且无弹窗、键盘或其他遮挡证据，才允许跨结构复用。移动目标、修改局部文字、禁用控件及不一致的局部签名仍会拒绝复用；多个匹配候选必须指向同一坐标。空 UI 树、纯色局部图块及缺少边界的目标只用精确指纹。名称或 Activity 本身不能授权复用。目标点周围的保护区域（至少 4 像素，否则为屏幕短边的 2%）或已有目标边界碰到被忽略的状态栏时，不写入也不复用。历史截图、设备或应用不明确、多候选/未找到、无效坐标均不缓存。收到纠错反馈或存在未解决的执行失败事件时，跨定位模式清理当前页面、相关结构快照及同名目标所在页面。能够关联到上一缓存动作时，也清理错误跳转的来源页面。设备级代次阻止清理前的识别请求重新写入旧坐标。缓存损坏、被占用或无法写入时继续正常定位。第 3 版页面指纹加入包名与 Android Activity，不会命中旧指纹，会通过正常定位重新学习位置。Android 无法确认 Activity 时跳过缓存复用；其他平台仍使用包名、像素和 UI 树校验。定位结果不等于点击目的已经达成，点击仍走原有执行器和验证流程。

## 后台与统计

后台顶部的“页面缓存”（`/cache`）按设备、包名和 Activity 分组展示，支持搜索 Activity，并展开查看页面指纹、元素名称/别名、坐标/边界、最近使用及保留状态。元素明细分页加载，可二次确认后按设备、应用及精确指纹清理一页。累计查询、命中率、未命中原因、预缓存使用率、查询/视觉定位平均耗时及执行下发/失败次数独立持久化，不随元素淘汰或清理重置；只从新版启用后开始记录，不反推旧数据。执行下发成功不等于任务目标验证成功，动作统计仅关联同截图下坐标完全一致的下一次操作。读取统计不修改 LRU 或迁移数据库。旧记录显示“未记录 Activity”，不会从包名反推。Flutter 等单 Activity 应用仍依靠主体像素和 UI 树区分内部页面。

## 本地存储

默认数据库为安装环境 `.env` 同目录下的 `.cache/visual_locations.sqlite3`，跨任务及进程重启保留，仅保存在本地且已被 Git 忽略。只保存位置元数据与指纹，不保存截图或模型完整回复。Flash、Pro/Ultra 和直接物体检测均支持多目标部分命中，只有剩余目标进入 OCR/模型。原图上的嵌套检测也可复用；裁剪、缩放和标注图不借用原图缓存。SQLite 使用 WAL，多目标查询和计数在一个短事务内完成。数据库不可用时优先保障正常定位，极端锁竞争或存储故障时的遥测可能缺失。

## 固定区域与失败案例

固定区域缓存用于减少页面动态内容造成的无效定位。当前识别底部导航栏、顶部工具栏、侧边导航，以及由至少两个有名称、分离且对齐的可点击控件构成的底部固定区域；不依赖具体应用包名，也不按固定底部百分比直接复用。缓存候选仍限定同一设备、应用、Activity 和尺寸，区域身份、边界、区域内完整像素与节点/状态必须一致。区域外列表增减、文字和图片变化、祖先节点汇总文字变化不会影响此范围。弹窗、键盘、其他窗口、跨界节点和可滚动祖先会阻止区域复用。选中状态、角标、主题变化仍可能导致安全的未命中；无 UI 证据的 Canvas 页面不自动放宽。已有旧缓存不会仅凭坐标升级为区域缓存，后续正常学习时才加入区域信息。区域候选复用原有元素行，不为每次动态页面变化复制条目。

后台元素明细显示“整页精确匹配”“整页结构 + 局部校验”或固定区域类型、区域标识和像素边界，累计统计单独显示固定区域命中。失败案例支持按设备、完整应用包名、原因筛选及分页，记录目标描述（最多 160 字符）、当前/来源页面指纹、Activity、复用范围、首次/最近时间和发生次数；相同条件合并，每设备保留最近 1000 组。原因包括无候选、区域节点/状态变化、区域像素变化、布局变化、遮挡、纠错清理以及缓存动作执行失败。案例留在本地数据库，不记录截图或完整 UI 树；清理元素不删除案例，案例淘汰不重置累计计数。旧版本未记录的失败不能追溯。

## 配置

在 `config/artemis.jsonc` 中统一配置缓存，打包模板也包含相同默认值：

```jsonc
{
  "agent": {
    "visual_location_cache": {
      "enabled": true,
      "batch_prefetch": true,
      "capacity_per_device": 10000
    }
  }
}
```

容量按设备计算，支持 1–100000 的整数，非法值会在配置校验时报错。Flash、Pro、直接图片定位和 SDK 构建的任务共享这一配置。将 `enabled` 设为 `false` 可关闭复用；原有 `.env` 开关 `ARTEMIS_VISUAL_LOCATION_CACHE=0` 仍可强制关闭。旧环境变量 `ARTEMIS_VISUAL_LOCATION_CACHE_CAPACITY` 不再读取，请将其数值移到 JSONC 的 `capacity_per_device`。`.env` 中可选的 `ARTEMIS_VISUAL_LOCATION_CACHE_PATH` 仍用于覆盖数据库路径。修改后需重启 ARTEMIS/MCP 进程。优化跳过的是重复视觉定位，主 Agent 的决策和设备动作仍按正常流程进行。

整页/结构查询每次最多检查最近 1000 条候选，区域和跨结构查询最多检查 256 条候选；这是查询上限，与每设备 10,000 条存储额度不同。扩大候选范围可减少较早保存的位置查不到的情况，但不保证每次查询扫描所有已存位置。
