# 安全探索学习：架构与实施基线

日期：2026-10-27。当前阶段：实施；方案由用户授权 AI 负责，后续不再逐门禁询问。

## 授权与确认

用户明确：“确认所有方案，无需再找我确认，你负责所有的方案和设计实现，我只看最后结果”。技术方案整体确认；后续设计、架构、任务拆分由实现负责人决定。此指令优先于通用 L3 技能的逐门禁确认要求，不代表免除测试或允许改变安全范围。严格 Figma 检查不启用：没有外部 Figma 输入，采用已确认交互规格和现有页面。

## 模块与状态归属

- `artemis/runtime/cache_exploration/store.py`：独立本地 SQLite，唯一任务状态、累计预算、幂等键、请求账与页面结果；每个修改在事务中验证状态/版本。
- `policy.py`：从实际 UI 树提取元素，过滤敏感上下文，校验导航/滑动/返回候选。模型只能选择观察内引用。
- `model.py`：任务专用、串行、有限超时的模型请求；复用配置与认证，严格计量，Codex 专用连接取消及资源回收，不动普通任务的连接。
- `worker.py`：每个激活任务独立进程，持有现有设备锁；观察、学习、策略、动作的闭环，先记账再派发，暂停/停止收敛后退出。
- 管理后台 service/router：只写控制意图、启动受控 worker、识别遗留进程和读取报告；不执行模型输出。前端独立组件负责配置与展示，不拥有运行生命周期。

## 数据流与一致性

开始→写入幂等任务→启动 worker→校验/设备锁→运行段→稳定观察→学习请求→结算用量→同段/同页校验→缓存写入→选择安全动作→预算预留→执行→再观察。

暂停/停止写入新状态并使旧段失效；worker 取消在途请求，丢弃旧结果，释放设备后终结该执行段。终态不可恢复；继续沿用任务预算并生成新段。API 成功接收控制不代表已经释放设备，UI 必须展示处理中。

账本与缓存不共享事务；写缓存时持有任务事务闸门，先后关系可验证。崩溃不重放设备动作，账本不明请求保留未结算。后台恢复只识别活跃 PID/创建时间，不自动重新运行。SQLite 迁移只加新表；旧缓存按既有迁移逻辑保留。

## 实施任务包与验证契约

全部使用通用 Profile；新增行为先写可隔离测试验证失败，再实现。`test-driven-development` 与 `verification-before-completion` 未列为可用技能，采用实际失败/通过命令及新鲜验证证据执行同样原则。

| 任务 | 可改范围 | AI 验证 | 人工/实机验证 |
| --- | --- | --- | --- |
| 持久化控制 | 新 runtime 包与单元测试 | 幂等、终态、并发控制、累计预算、崩溃识别 | 关闭重开后台不会自动执行 |
| 模型/安全/学习 | 新适配、worker，必要缓存复用入口 | 缺失用量、取消、敏感拦截、迟到写入、重试边界、XML 页学习 | 实机导航及模型调用；不能用 mock 充当实际推理 |
| API 与 UI | 新 service/router/component；服务器及缓存页最小接线 | 来源/授权校验、重复请求、错误状态、前端测试/构建 | 多宽度配置/运行/暂停/终态截图及可读性 |
| 交付 | 中英文 README、验收报告 | 相关回归、敏感扫描、原有无关文件保留 | 无法验证项明确列出，不自动视为通过 |

设计还原候选：缓存页新探索面板；不启用严格检查，用户已授权实现负责人决定且无 Figma 输入。TDD 范围聚焦状态、预算、安全与异常，不为静态文案写镜像测试。编写手机测试前已通过 ARTEMIS 自诊断和实际层级观察，确认了唯一设备及设置导航页面；不将其等同于新功能端到端通过。

## 风险与变更控制

供应商可能无法回报取消后最终用量：保留未知、禁止继续消费；模型可能误判语义：程序策略与未知拒绝，明确有限覆盖。资源上界沿用技术方案。不得以实现便利取消预算/安全/恢复要求。遇到外部环境阻碍先完成可执行工作并保留验证缺口，不再为普通方案选择询问用户。

保留已有改动；不主动提交、推送或安装全局版本。最终验收必须区分受控测试、浏览器运行、真实设备/推理和待人工体验确认。
