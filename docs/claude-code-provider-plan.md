# Claude Code 客户端接入计划

基线：`2d9eb9f`；实现分支：`codex/claude-code-provider`。用户已确认按调研推荐路线推进完整实现，不再重复询问技术路线。原有未跟踪本地测试保持原样。

## 目标与边界

- 新增独立 `claude_code` Provider，不替换 Anthropic API，不改变默认 Codex 配置。
- 用户最新确认：Codex 与 Claude Code 两套独立配置，以显式开关选用，不实现两者之间的备用或自动回退。切换保留另一套配置和认证，仅选中项进入运行时路由。
- 通过未修改的官方 CLI 进行本机推理，使用官方认证状态和登录命令，不读取、复制或保存令牌，不新增第三方 OAuth 登录。
- 保持 ARTEMIS 执行动作的闭环；Claude 只返回模型结果，不获得内置工具、嵌套 MCP、用户插件或项目钩子执行权限。组织强制策略不得绕过。
- 复用现有图像压缩、LangChain 消息/工具接口、LLM 网关、失败回退、步骤历史、缓存和遥测；不复制 Codex 私有协议或其内部 Helper。
- 任务启动、CLI、SDK、MCP、后台 Run Task 使用同一个认证与预检判定。非必需 Provider 的凭据不能阻断 Claude Code，其他实际主路由仍须有效。
- 后台提供安装/登录指引、脱敏诊断、独立的最小推理验证和配置能力。普通轮询不触发付费推理。
- 订阅账号仅由用户在原版 CLI 自行授权和使用；不承诺第三方产品可以代理订阅额度。API/云凭据路线保留，公开发布需遵守 Anthropic 条款。

## 执行顺序

1. 传输与适配器：发现原版 CLI、能力与认证探测、隔离运行、NDJSON 图片输入、结构化结果、工具参数校验、使用量/缓存计数、超时/取消与进程清理。
2. 全入口接入：配置类型、模型工厂、主节点凭据诊断、任务预检、模型连通性检查、MCP 故障修复提示；保留 Codex/API 兼容性。
3. 后台：显式客户端开关、独立配置保存、本机同源诊断接口、最小推理验证、认证面板和错误/未安装/未登录/已登录状态，Run Task 不另建模型调用路径。
4. 验证：单元异常测试、真实子进程协议测试、官方 CLI 无账号测试、后台与 MCP 启动链路、前端测试和生产构建、现有回归、隐私扫描。
5. 文档和验收：配置/依赖/条款边界/恢复命令及状态说明，保留真实账号验收清单，区分模拟闭环与实际推理。

## 关键决策

- 原版 CLI 没有与 Codex App Server 等价的公开多线程 RPC，首版每次模型调用独立进程/会话，输入历史由 ARTEMIS 提供；不通过复用同一对话污染不同角色、设备或任务。冷启动延迟需真实账号基准验证。
- 图像以协议内存消息发送，临时系统指令如需落盘必须使用私有目录并在成功、失败、超时及取消路径清理；CLI 对话持久化关闭。
- CLI 版本不能只看名称；必须具备隔离和结构化输出所需参数，不支持时在手机操作前明确失败，不能静默减少安全限制。
- 普通预检只能证明本机认证和配置可用；没有公开模型目录时不伪造目录或宣称推理权限通过。实际访问由用户显式触发的 READY 请求验证。

## 证据与完成标准

- 每个生产改动配套可执行测试；优先编写失败用例，再实现。
- 模拟程序只用于测试环境，生产没有跳过认证的测试开关或假模型通道。
- 全链路测试覆盖文本、图像、工具、回退、认证缺失/失效、异常 JSON、额度错误、并发隔离、超时取消、用户配置/MCP 不继承、后台同源隐私边界。
- 用户目前无 Claude 账号：真实 Claude 推理和 Claude 驱动真机属于待人工验收，不能以模拟、已有 Codex 真机结果或 CLI 未登录结果替代。其余可验证项持续完成。
- 不自动提交、推送或修改全局用户模型配置；需要时只用独立临时配置验证，不干扰已有服务和任务。
